# v2.16.0

GPT-6 Sol and GPT-6 Luna are supported, and every model OpenAI or upstream
Codex has retired now runs on its named replacement instead of being sent under
a name the backend no longer serves. Retired model ids in existing configs keep
working. Accounts and pools are unchanged.

Landed as [#696](https://github.com/ndycode/codex-multi-auth/pull/696),
[#697](https://github.com/ndycode/codex-multi-auth/pull/697) and
[#698](https://github.com/ndycode/codex-multi-auth/pull/698).

## What was wrong

**GPT-6 Sol and Luna ran GPT-6 Astra.** Upstream Codex added `gpt-6-sol` and
`gpt-6-luna` on 2026-09-22. In 2.15.0 the GPT-6 resolver sent every GPT-6 id
it did not recognise to Astra, so a `gpt-6-luna` request ran the frontier model
at $10 / $50 per 1M tokens instead of Luna's $0.10 / $0.50, against Astra's
entitlement and rate limits.

**Retired models were still routed under their own names.** Every model older
than GPT-5.5 is retired:

- OpenAI's deprecations page lists the codex models and the `*-chat-latest`
  snapshots as shut down.
- The upstream Codex catalog removed `gpt-5.1`, `gpt-5.2`, `gpt-5.3-codex` and
  `gpt-5.4-mini`. `gpt-5.4` carries `retirement_at: 2026-08-31` and the notice
  "GPT-5.4 is no longer available".

2.15.0 still sent those ids as-is. Three core paths also pointed at dead models:

- The unsupported-model fallback ended on `gpt-5.4`.
- The quota probe fell back through `gpt-5.4`, `gpt-5.3-codex`,
  `gpt-5.2-codex` and `gpt-5-codex`.
- Every codex id routed to `gpt-5.3-codex`.

**Large GPT-6 requests were under-priced.** OpenAI bills prompts with more than
272K input tokens at a higher long-context rate. The cost estimator always used
the short-context rate, so a large Astra session was under-counted and a
`maxCostUsd` budget could overrun.

**`status -m <codex model>` read the wrong account slot.** The runtime proxy
keys a codex request by the model's prompt family (`gpt-5-codex` in 2.15.0).
The wrapper's status lookup read `codex`, a key the proxy did not write for
those requests.

## What's fixed

- `gpt-6-sol` and `gpt-6-luna` resolve to their own models, with the upstream
  catalog's reasoning ladders. Sol runs `low` through `ultra` and Luna `low`
  through `max`, and both default to `medium`. They are priced at the published
  rates, Fast mode included, and listed in both config templates. A `gpt-6-terra`
  id resolves to Sol. Bare `sol`/`luna` still mean the GPT-5.6 tiers.
- Retired ids run on the replacement OpenAI names:

  | Retired | Now runs as |
  | --- | --- |
  | any codex id (`gpt-5.3-codex`, `gpt-5-codex`, `codex-max`, ...) | `gpt-5.6-sol` |
  | codex minis (`codex-mini-latest`, `gpt-5.1-codex-mini`, ...) | `gpt-5.6-terra` |
  | `gpt-5.4` | `gpt-6-sol` |
  | `gpt-5.4-mini`, `gpt-5.4-nano` | `gpt-6-luna` |
  | `gpt-5.4-pro`, `gpt-5.2-pro` | `gpt-5.5-pro` |
  | `gpt-5.2`, `gpt-5.1`, all `*-chat-latest` | `gpt-5.6-sol` |
  | `gpt-5-mini` / `gpt-5-nano` | `gpt-5.6-terra` / `gpt-5.6-luna` |

  Effort-suffixed and provider-prefixed forms resolve the same way. A retired id
  that reaches the backend through the pass-through proxy steps once to its
  replacement on the unsupported-model response. Usage recorded under a retired
  id is priced at the replacement's rate. Cost already in the ledger is not
  re-priced.
- The fallback chain ends at `gpt-5.5` / `gpt-5.5-pro`. The quota probe chain is
  `gpt-5.6-sol`, `gpt-5.5`, `gpt-6-luna`.
- GPT-6 requests with more than 272,000 input tokens use the published
  long-context rates, standard and Fast.
- `status -m` reports the family the proxy actually keys.

## Behaviour changes to know about

- Codex ids now use the `gpt-5.2` prompt family and rotation bucket, like every
  live model. A per-family account assignment saved under `gpt-5-codex`,
  `codex-max` or `gpt-5.1` is no longer consulted.
- A direct `gpt-5.6-luna` or `gpt-5.6-terra` request that gets an
  unsupported-model response now retries on `gpt-5.5`, where it used to stop.
  The wrapper retries unconditionally. The plugin host retries only when
  `fallbackOnUnsupportedCodexModel` is on.
- `fallbackToGpt52OnUnsupportedGpt53` is kept for config compatibility but has
  no effect.
- The context budget guard no longer estimates a window for codex ids, because
  they now run on `gpt-5.6-sol`, which it deliberately does not estimate.

## Upgrade notes

No migration is required. Existing accounts, pools and configuration are
unchanged.

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.16.0`.
